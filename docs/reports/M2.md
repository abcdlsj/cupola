# M2 — hub

Status: delivered; exercised end to end against the three fictional demo agents
and against the real macOS agent.

## What ships

- SQLite (`modernc.org/sqlite`, WAL, one writer), embedded migrations: nodes,
  samples, 1 m/1 h rollups, disk/net/process samples, latest snapshot, actions,
  events, action runs, rules, alerts, alert state, channels, deliveries, tokens,
  settings.
- Poller: 5 s default, 8 concurrent polls, 12 s timeout, per-node failure count
  and offline after 3 failures, change events (reboot, failed unit, container
  state/restarts, new listening port), rollups and retention every 10 minutes
  (48 h / 30 d / 13 mo, min/avg/max; events and runs 90 d).
- Auth: Argon2id admin password (64 MiB, 4 lanes), HMAC-signed session cookie,
  hashed API tokens with `read` / `actions:run`, node and action allowlists,
  expiry, revocation, rate limits, CSRF checks on cookie writes.
- Alerts: metric rules (CPU, memory, load, disk, inode, temperature, PSI) with a
  duration gate, resolve notifications and cooldowns; event rules on kind,
  severity and node; per-node state machine.
- Channels: generic webhook, ntfy, Discord, Slack, Telegram; 5 s timeout, three
  attempts, no redirects, DNS resolved then every address checked (loopback,
  private, link-local, CGNAT, ULA blocked unless opted in), HMAC-SHA256
  signature, encrypted URLs/secrets, delivery rows.
- Action proxy: allowlist + `allow_api` + rate limit, synchronous result, audit
  row and event, truncated output.
- API: fleet, nodes CRUD/test, snapshot, series with table selection and
  downsampling, parts, actions, runs, agents, events, alerts, rules, deliveries,
  channels, tokens, settings, SSE.
- Embedded agent for `cupola serve` with a generated token and a 0600 local
  config; optional Bolthole dialer for nodes.
- Tests: store round trip, rollup/retention, event/rule/token scan, crypto
  (AES-GCM, Argon2id, sessions, token shape), SSRF ranges, and an httptest
  end-to-end: login → add node → poll → summary → series → token → scoped run →
  allowlist refusal → audit/event.

## Verification

- Three demo agents polled; events derived from changed snapshots; an event rule
  delivered to a local webhook with a valid signature; a metric rule fired and
  resolved.
- A token with `actions:run` but a mismatched action allowlist got 403; the admin
  run succeeded and produced an audit row and an event.
- The offline path (port 9) produced a `node` critical event without putting the
  target address in the message.
