# M4 — hardware detail, services, containers, alerts

Status: delivered as part of M1–M3, verified where the hardware allowed.

## What ships

- Storage: per-mount usage, inodes, read/write bytes and IOPS, read latency,
  read-only flag; 7-day fill prediction fitted in the hub and shown as days to
  full.
- Network: per-interface counters, rates, errors/drops, speed, duplex, driver;
  conntrack count.
- Sensors: hwmon temperatures with high/critical thresholds; fans are not
  reported by the current gopsutil version and are omitted.
- GPU: NVIDIA through NVML (cgo build) with per-process VRAM, AMD through sysfs
  (util, VRAM, temperature, power).
- SMART: health, temperature, wear, reallocated sectors, power-on hours through
  smart.go and a smartctl JSON fallback.
- Services: systemd units with failed filter, restarts and enabled state.
- Containers: state, image, ports, uptime, CPU/memory, restart count; Docker and
  Podman through the Docker-compatible socket.
- Ports: protocol, address, port, owning process, cgroup and container.
- Updates: opt-in pending apt/dnf counts (6 h cache).
- Alerts: metric rules for CPU, memory, load, disk, inodes, temperature and PSI;
  event rules; resolve notifications; cooldowns; delivery history; channel test.

## Verification

- beelink: sensors (NVMe, coretemp), containers, units and ports collected;
  SMART empty without root; no GPU present.
- macOS dev: sensors, containers unavailable (no Docker socket), GPU/SMART empty.
- Demo agents in the UI: GPU, SMART, containers, sensors, services and events
  render on the node tabs.
- Alert delivery: a local webhook received a test alert and a fired rule with an
  HMAC signature; a recovery produced a resolved alert.
